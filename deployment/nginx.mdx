Nginx is a high-performance reverse proxy that can front `doh-server` with TLS termination, HTTP/2 multiplexing, OCSP stapling, and a hardened set of security headers. This guide walks through a production-ready Nginx server block that satisfies all the requirements for a reliable DNS-over-HTTPS deployment.

## Prerequisites

- `doh-server` installed and listening on `127.0.0.1:8053` (the default from `doh-server.conf`).
- Nginx compiled with SSL support (standard in most distributions).
- A valid TLS certificate and private key (e.g. issued by Let's Encrypt).
- Nginx version ≥ 1.3.7 for OCSP stapling support; ≥ 1.20.0 for TLS 1.3.
- A DH parameters file generated with:
  ```bash
  openssl dhparam -dsaparam -out /etc/nginx/dhparam.pem 4096
  ```

## Nginx Server Block Configuration

Add the following `server` block to your Nginx configuration (e.g. `/etc/nginx/conf.d/doh.conf`):

```nginx
server {
  listen       443 ssl http2 default_server;
  listen       [::]:443 ssl http2 default_server;
  server_name  MY_SERVER_NAME;

  server_tokens off;

  ssl_protocols TLSv1.2 TLSv1.3;          # TLS 1.3 requires nginx >= 1.20.0
  ssl_prefer_server_ciphers on;
  ssl_dhparam /etc/nginx/dhparam.pem;     # openssl dhparam -dsaparam -out /etc/nginx/dhparam.pem 4096
  ssl_ciphers EECDH+AESGCM:EDH+AESGCM;
  ssl_ecdh_curve secp384r1;               # Requires nginx >= 1.1.0
  ssl_session_timeout  10m;
  ssl_session_cache shared:SSL:10m;
  ssl_session_tickets off;                # Requires nginx >= 1.5.9
  ssl_stapling on;                        # Requires nginx >= 1.3.7
  ssl_stapling_verify on;                 # Requires nginx => 1.3.7
  ssl_early_data off;                     # 0-RTT, enable if desired - Requires nginx >= 1.15.4
  resolver 1.1.1.1 valid=300s;            # Replace with your local resolver
  resolver_timeout 5s;
  # HTTP Security Headers
  add_header X-Frame-Options DENY;
  add_header X-Content-Type-Options nosniff;
  add_header X-XSS-Protection "1; mode=block";
  add_header Strict-Transport-Security "max-age=63072000";
  ssl_certificate /path/to/your/server/certificates/fullchain.pem;
  ssl_certificate_key /path/to/your/server/certificates/privkey.pem;
  location /dns-query {
    proxy_pass       http://localhost:8053/dns-query;
    proxy_set_header Host      $host;
    proxy_set_header X-Real-IP $remote_addr;
  }
}
```

<Note>
  Replace `MY_SERVER_NAME` with your actual domain name (e.g. `doh.example.com`). Update `ssl_certificate` and `ssl_certificate_key` to point to your certificate's `fullchain.pem` and `privkey.pem` files. If you use Let's Encrypt with Certbot, these are typically found under `/etc/letsencrypt/live/YOUR_DOMAIN/`.
</Note>

## Key Directives Explained

### `proxy_pass http://localhost:8053/dns-query`

Forwards all requests that match the `/dns-query` location to the locally running `doh-server`. Because `doh-server` defaults to listening on both `127.0.0.1:8053` and `[::1]:8053`, either `localhost` or `[::1]` can be used here.

### `proxy_set_header X-Real-IP $remote_addr`

Passes the connecting client's IP address to `doh-server` via the `X-Real-IP` header. `doh-server` reads this header and uses it to populate the EDNS0-Client-Subnet (ECS) option in the upstream DNS query. ECS allows GeoDNS and CDN providers to return geographically appropriate answers. Without this header, all upstream queries would appear to originate from the server's own IP.

### `ssl_stapling on` and `ssl_stapling_verify on`

Enables OCSP stapling, where Nginx periodically fetches the certificate's revocation status from the CA and includes it in the TLS handshake. This eliminates the need for clients to perform a separate OCSP lookup — which is critical because that lookup itself requires DNS, creating a circular dependency if DNS is unavailable on startup.

### `listen 443 ssl http2`

Enables HTTP/2 on port 443. HTTP/2 multiplexing allows many concurrent DNS queries to be sent over a single TCP connection, significantly reducing latency compared to HTTP/1.1 for clients that issue multiple queries in quick succession.

### `ssl_protocols TLSv1.2 TLSv1.3`

Restricts the server to TLS 1.2 and 1.3 only, disabling older insecure versions. TLS 1.3 is preferred when both sides support it.

## Testing the Configuration

After reloading Nginx (`sudo nginx -s reload`), verify that the DoH endpoint is responding correctly:

```bash
curl -H 'accept: application/dns-json' \
  'https://your.server/dns-query?name=example.com&type=A'
```

A successful response will be a JSON object containing the DNS answer for `example.com`:

```json
{
  "Status": 0,
  "TC": false,
  "RD": true,
  "RA": true,
  "AD": false,
  "CD": false,
  "Question": [{ "name": "example.com.", "type": 1 }],
  "Answer": [{ "name": "example.com.", "type": 1, "TTL": 3600, "data": "93.184.216.34" }]
}
```
