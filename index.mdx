DNS-over-HTTPS (DoH) encrypts your DNS queries by tunneling them over HTTPS, preventing eavesdropping and tampering on the network. This project provides both a **client** (`doh-client`) that accepts standard DNS queries and proxies them over HTTPS, and a **server** (`doh-server`) that you can deploy behind a reverse proxy to run your own DoH resolver. Both components support the [Google DNS-over-HTTPS JSON protocol](https://developers.google.com/speed/public-dns/docs/dns-over-https) and [IETF RFC 8484](https://www.rfc-editor.org/rfc/rfc8484.txt) wire-format.

## What's included

<CardGroup cols={3}>
  <Card title="doh-client" icon="arrow-right-arrow-left">
    A local DNS proxy that listens on UDP/TCP port 53 and forwards queries to a DoH upstream over HTTP/2.
  </Card>
  <Card title="doh-server" icon="server">
    An HTTP server that receives DoH requests and resolves them against a traditional upstream DNS resolver.
  </Card>
  <Card title="json-dns library" icon="brackets-curly">
    A reusable Go package for marshalling and unmarshalling DNS messages to/from the Google JSON format.
  </Card>
</CardGroup>

## Key features

<CardGroup cols={2}>
  <Card title="Dual Protocol Support" icon="layer-group" href="/features/protocols">
    Supports both Google DNS-over-HTTPS JSON and IETF RFC 8484 wire-format in the same binary.
  </Card>
  <Card title="HTTP/2 Transport" icon="network-wired" href="/features/protocols">
    All upstream requests use HTTP/2 with TLS for multiplexed, low-latency encrypted DNS queries.
  </Card>
  <Card title="Load Balancing" icon="scale-balanced" href="/configuration/upstream-selectors">
    Three upstream selector strategies: random, weighted round-robin, and LVS weighted round-robin.
  </Card>
  <Card title="EDNS0-Client-Subnet" icon="globe" href="/features/edns0-client-subnet">
    Forwards a masked client IP to upstream resolvers for GeoDNS and CDN optimization.
  </Card>
  <Card title="DNSSEC Compatible" icon="shield-check" href="/features/dnssec">
    Passes DNSSEC signatures through to validating resolvers like Unbound or BIND.
  </Card>
  <Card title="TLS Client Auth" icon="lock" href="/features/tls-client-auth">
    Optionally require mutual TLS client certificate authentication on the server.
  </Card>
</CardGroup>

## Get started

<Steps>
  <Step title="Install Go and build">
    Install Go 1.20 or newer, then run `make` to build both binaries.
  </Step>
  <Step title="Install as system services">
    Run `sudo make install` to install binaries and systemd unit files.
  </Step>
  <Step title="Start the client">
    Enable and start `doh-client.service` with systemctl, then point your system DNS to `127.0.0.1`.
  </Step>
  <Step title="Verify it works">
    Run `dig www.google.com` and confirm the server shows `127.0.0.1#53` in the output.
  </Step>
</Steps>

<Note>
  All log output from both `doh-client` and `doh-server` is written to **stderr**. When running under systemd, view logs with `journalctl -u doh-client` or `journalctl -u doh-server`.
</Note>
